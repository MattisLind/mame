# System 8000 8-inch Winchester Disk Controller

The `wdc` option in `slot_disk` implements the host command interface of the
8-inch Winchester controller photographed in `picture/S8000/WDC`. It uses
four `harddisk_image_device` drives, `-hard1` through `-hard4`, corresponding
to controller units 0 through 3. Transfers use logical sectors in CHD images,
as with the existing SMDC and the MWDCII sector adapter.

This board has a Z80, a CTC and three DMA chips. Its command interface differs
from the Z8001-based MWDCII. The implementation is high-level: the supplied
ROMs are audited, but the controller CPU, DMA chips and discrete formatter
do not execute. Commands complete asynchronously after a provisional
100 microseconds. CRC/ECC, flux, rotational timing, retries, head offsets and
physical defect injection are omitted. No CPU clock is guessed for this
command-level device.

## Prepare ROMs and a disk

Run from the repository root:

```sh
python3 scripts/s8000/prepare_wdc.py
./s8000d -verifyroms s8k_wdc -rompath roms
python3 scripts/s8000/create_wdc_image.py build/s8000-wdc.chd --heads 3
```

The ROM preparer checks Intel HEX checksums, capture sizes, hashes and the
Z80 reset vector. These are consecutive 4 KiB ROMs, not interleaved ROMs.

| Socket | MAME filename | Address | CRC32 |
|---|---|---|---|
| U27 | `wdc_34-0611-01.u27` | 0000–0fff | 2d1c88f3 |
| U28 | `wdc_34-0612-01.u28` | 1000–1fff | 0575cfd8 |

ROM bytes 3 and 4 identify firmware 6.1 and board 1.1. Native WDCMON prints
those revisions from the FIRMID response.

Supported geometries have **605 physical cylinders, 600 logical cylinders,
24 sectors per track and 512 bytes per sector**, with **1, 3, 4 or 5 heads**.
These are the drive-type choices in the supplied firmware at `11e5..1225`.
The default three-head drive has 22,118,400 logical bytes. Image mounting
rejects incompatible geometry.

The helper creates an uncompressed, directly writable CHD and retains its
intermediate `.raw` file. Existing outputs are never overwritten. Normal
addressing maps logical cylinder 0 to physical cylinder 1, reserving cylinder
0 for metadata and the final four cylinders for spares. CE mode exposes all
605 physical cylinders. An empty defect table starts with `ffff`; copies
occupy sector 0 of each head on physical cylinder 0. The eight bytes at sector
offset 504 contain logical cylinders, heads, sectors, physical cylinders,
sectors per cylinder and a reserved byte. Multi-byte metadata fields are
big endian. The format commands recreate this metadata.

Compressed CHDs use MAME's normal differencing images under `diff/`.
The helper uses `-c none` so installation and scratch-disk writes reside in
the selected CHD itself. A newly created disk has no installed operating
system; ZEUS installation/boot on WDC has not been verified in this work.
The original kernel's `zd` driver has now been verified as a secondary disk
alongside SMDC and a bootable MWDCII disk: concurrent file copies, tape
round trips, filesystem checks and restart persistence all pass. See
[the multi-user stress notes](s8000-multiuser-stress.md), including the
WDC word-I/O compatibility fix required by ZEUS.

## Start SADIE with WDC and TCC

Prepare the CPU and TAP media as described in
[the MWDCII notes](s8000-mwdcii.md) and [the TCC notes](s8000-tcc.md), then:

```sh
./s8000d s8000 -rompath roms \
  -slot_disk wdc -hard1 build/s8000-wdc.chd \
  -slot_tape tcc -tape1 roms/tapes/sadie-3.5.tap
```

At the system monitor enter `Z T` to boot SADIE from the native three-track
TAP image. Select `T` at SADIE's command level and choose one of:

| Choice | Program | Purpose |
|---|---|---|
| 12 | WDCFMT | Format the disk and display its defect map |
| 13 | WDCMEDIA | Write, read and compare every logical track with three patterns |
| 14 | WDCTEST | Random single-sector or random-length transfers |
| 15 | WDCMON | Interactive controller command monitor |
| 16 | WDCCRC | Read every logical track and report controller errors |

WDCFMT, WDCMEDIA and WDCTEST destroy disk contents. Use a disposable image.
WDCTEST parameter 2 selects subtest 1 or 2. WDCMON is a monitor, rather than
an exhaustive automated test; its format/write commands are destructive too.

## Verified diagnostics

The original SADIE 3.5 programs booted through TCC without patched guest code
and completed the following runs on a three-head drive:

| Program | Work completed | Result | Transcript directory under `build/` |
|---|---|---|---|
| WDCFMT 2.1 | One full format and defect-map read | Zero errors, no defective sectors | `s8000-wdc-format-final` |
| WDCTEST 2.1, test 1 | 128 random sector writes and 128 read comparisons | Zero errors | `s8000-wdc-test1` |
| WDCTEST 2.1, test 2 | 10 random-length write/read pairs and memory corruption checks | Zero errors | `s8000-wdc-test2-final` |
| WDCMEDIA 2.2 | All 1,800 logical tracks, three patterns; 5,400 writes and 5,400 reads | Zero errors | `s8000-wdc-media` |
| WDCCRC 2.1 | All 1,800 logical tracks; 43,200 sectors | Zero errors | `s8000-wdc-crc` |
| WDCMON 3.1 | IDs, NULL, HOME, SEEK, FILL/WRITE/READ/COMPARE, FRD, FWR without a defect, CE mode, defect-table reload, status | All commands completed; compare error count zero | `s8000-wdc-monitor-final` |

Each directory contains `console.txt` and `mame.log`. WDCCRC passing establishes
a complete successful read scan of healthy sector media. It does not establish
CRC calculation or injected-media-error recovery, which are deliberately
outside this implementation.

Reproduce the runs with a disposable image:

```sh
python3 scripts/s8000/check_sadie_wdc.py --disk build/s8000-wdc.chd \
  --diagnostic WDCFMT --output build/wdc-format
python3 scripts/s8000/check_sadie_wdc.py --disk build/s8000-wdc.chd \
  --test 1 --output build/wdc-test1
python3 scripts/s8000/check_sadie_wdc.py --disk build/s8000-wdc.chd \
  --test 2 --output build/wdc-test2
python3 scripts/s8000/check_sadie_wdc.py --disk build/s8000-wdc.chd \
  --diagnostic WDCMEDIA --output build/wdc-media --timeout 1800
python3 scripts/s8000/check_sadie_wdc.py --disk build/s8000-wdc.chd \
  --diagnostic WDCCRC --output build/wdc-crc --timeout 600
python3 scripts/s8000/check_sadie_wdc.py --disk build/s8000-wdc.chd \
  --diagnostic WDCMON --output build/wdc-monitor
```

The harness checks successful exit, error totals, the selected WDCTEST subtest
and expected transfer counts, including complete scans for WDCMEDIA/WDCCRC.
It responds to menu prompts and captures the console; it does not inject code.
WDCMON's FRD parser requires a length argument despite its HELP text omitting
it: `FRD 1 2048 261 20 0 0` reads cylinder 20 into `<1>0800H`.

Additional register-level checks run with:

```sh
python3 scripts/s8000/check_wdc.py --output build/wdc-probe
```

This creates disposable images for all four geometries. It verifies transfers
across head, cylinder and DMA 64 KiB boundaries, a partial final sector, guard
bytes outside DMA buffers, CE format-read headers/metadata, invalid parameters,
drive-end overflow, absent drives and read-only ZIP media. It also checks the
actual interrupt tag pushed onto the Z8001 guest stack, repeats reads after
restarting MAME, and extracts the CHDs to verify the exact saved payload bytes.
It also rejects a CHD with incompatible geometry. The recorded successful
run is `build/s8000-wdc-probe-complete`.

## Recovered host interface

The firmware receives a byte-register command block at host I/O `8000..800f`.
Host word I/O still obeys the Z8001's odd-address byte swapping.

| Register | Value |
|---|---|
| 8000 | Command bits 0..4; bit 5 requests a completion interrupt |
| 8001 | Unit 0..3 |
| 8002 | Head |
| 8003..8004 | Cylinder, little endian |
| 8005 | Sector; bit 7 marks a defect for FWR on physical hardware |
| 8008..8009 | Transfer count in words, little endian |
| 800a..800b | DMA address low 16 bits, little endian |
| 800c | DMA address high byte |
| 8010 | Controller status when read; acknowledge completion interrupt when written |

DMA is on physical ZBI RAM, bypassing CPU MMUs. It handles full tracks and
partial-sector transfers, and preserves bytes beyond a short write. READY
clears while a command is pending. Successful completion returns `99`, invalid
commands `9a`, and hard errors with operation-error detail `9d`.
The interrupt tag combines the programmed vector in its low byte with
`unit << 4 | completion` in its high byte. Completion codes are 0 for success,
1 for a hard error and 8 for an invalid command. RDS transfers six bytes:
drive-ready, disk-status, cylinder high/low, operation-error and new-status.
It preserves the preceding error so the guest can inspect absent-drive and
write-protection failures.

| Code (hex) | Command | Implemented behavior |
|---|---|---|
| 00 | NULL | Complete |
| 01 / 02 | READ / WRITE | CHS sector DMA, count in words |
| 03 | RDS | Detailed status DMA |
| 04 | HOME | Seek physical cylinder zero |
| 05 / 13 | Format / rebuild-format | Clear sector data and recreate no-defects metadata |
| 06 | SEEK | Translate address according to CE mode |
| 07 | SETOFF | Complete; head offsets are abstracted |
| 0b | FRD | Synthesized eight-byte header, 512-byte payload, two zero CRC bytes |
| 0c | SETVECTOR | Set interrupt vector from sector register |
| 0e | DIAG | Complete; internal controller RAM/CPU are abstracted |
| 0f / 14 | CEMODE / EXITCE | Switch physical/logical addressing |
| 12 | RBDT | Read no-defects map and leave CE mode |
| 15 | FIRMID | Firmware 6.1, board 1.1, EXTID length 12 words |
| 16 | EXTID | Four six-byte drive geometry records: logical cylinders, heads, sectors, physical cylinders |
| 17 | FWR | Accept the canonical good-sector header; reject defect injection |

The firmware command table is at `0895`; ID handlers are at `0801`/`0835`;
metadata construction is at `0966`; command completion is at `03f8`.
The supplied firmware rejects codes `08..0a`, `0d`, `10` and `11`, even though
WDCMON HELP lists some commands from other firmware revisions. The device
reports invalid-command completion for those codes as well. Nonempty defect
tables and intentionally bad format headers remain unsupported.
