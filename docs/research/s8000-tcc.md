# System 8000 cartridge tape controller

The `tcc` option in `slot_tape` emulates the host command interface of the
09-0208 Cartridge Tape Controller. The supplied captures in `roms/S8000/TCU`
and the board photograph in `picture/S8000/TCU` are the evidence for this board.
The manufacturer's abbreviation is TCC; the capture directory is named TCU.

This is high-level, record-based emulation, comparable to the existing SMDC.
The Z80B ROMs are registered and audited, but their instructions and the TTL
formatter do not run. Writable TAP images support WRITE, WFM and record-level
erase-gap handling. Read-only files and ZIP members report PROT and reject
writes. Transport timing is provisional
(100 microseconds per host command). CRC, NRZ encoding, flux and physical tape
motion are omitted. These limits still allow the original monitor, SADIE and
standalone ZEUS installer to use the controller without code patches.

## ROMs and clock

Run from the repository root:

```sh
python3 scripts/s8000/prepare_tcc.py
```

The script validates Intel HEX checksums, dump hashes and the firmware's
8-bit sum before writing the binary files into `roms/s8k_tcc`.

| Socket | MAME filename | Address | CRC32 |
|---|---|---|---|
| U97 | `tcc_34-0607-01a.u97` | 0000–07ff | 106a23a2 |
| U96 | `tcc_34-0608-01a.u96` | 0800–0fff | ebc69875 |

The photo shows a Z80B and a BCLK test point, with no local crystal. The ZBI
connector supplies BCLK at P1 pin 91 and MCLK at pin 59. A bus-derived clock
is therefore plausible, but the Z80 divider has not been established. The
current command-level implementation needs neither a CPU clock nor a guessed
divider. A future firmware-driven implementation will require the clock path
and the discrete formatter/FIFO handshake to be traced.

## Tape images and track markers

[Tpaxia's tape builder](https://github.com/tpaxia/Zilog_S8000/blob/5c874c92c7968812dd1a1368e8053159726341fa/tapes/build_tape_images.py)
writes SIMH records: little-endian length, payload, padding for odd lengths,
and a matching length trailer. Zero is a file mark; `ffffffff` ends the medium.
The SIMH error flag is retained and reported as a data error when read, with
the configured retry count. CRC/ECC calculation is not emulated.
Malformed lengths, trailers, track markers and unsupported special markers
are rejected at mounting time.

SADIE adds standalone `70000000 | track` markers, with no trailer. Its three
tracks remain separate, with file numbering restarting on each track. MODE 1
selects independent tracks; STRK rewinds the selected track. MODE 0 traverses
the tracks as one logical stream. Ordinary TAP files without track markers
occupy track 0. There are four cartridge image devices, `-tape1` through
`-tape4`, corresponding to controller units 0 through 3.

Fetch the pinned, hash-checked images using the existing media preparer:

```sh
python3 scripts/s8000/prepare_sadie.py --download \
  --manifest scripts/s8000/tape-media.json
```

For a local Tpaxia checkout, replace `--download` with `--source /path/to/Zilog_S8000`.
This produces `roms/tapes/sadie-3.5.tap` and
`roms/tapes/zeus-3.21-install.tap`. CPU ROM preparation remains documented in
[the MWDCII notes](s8000-mwdcii.md).

## Writable cartridges

Create a blank cartridge and mount it on the TCC:

```sh
python3 scripts/s8000/create_tcc_tape.py build/s8000-scratch.tap
./s8000d s8000 -slot_disk mwdcii -slot_tape tcc \
  -hard1 build/s8000-tcc-zeus-install.chd \
  -tape1 build/s8000-scratch.tap -rompath roms \
  -slot_cpu:cpu_a:sio0:chb:console terminal \
  -window -ui_active -uimodekey F12
```

MAME's File Manager also offers **Create** for each cartridge device. Regular
TAP files mount writable when filesystem permissions permit it. A write
replaces the remainder of its selected track; other tracks are preserved.
File marks are zero-length SIMH markers. Every command flushes the image, and
the persisted image can be mounted again after closing MAME.

**Capacity per track** in Machine Configuration defaults to a provisional
16 MiB of payload per track. These are virtual EOT limits, not switches on the
original board. The 256 KiB scratch option makes SADIE TEX reach EOT quickly.
The implementation sums payload up to the current position, counting each file
mark as one byte, without accounting for physical gaps or framing. MODE 0
writes continue onto the next track; MODE 1 stops at the selected track's
capacity. The ordinary limits are too large or otherwise arbitrary for actual
DEI cartridges; the physical capacity evidence below does not yet calibrate
the implementation.

Erase gap (command `000d`) is approximated by marking the next record damaged
without changing its logical position. It preserves subsequent records and
uses the SIMH error flag so the damage survives remounting. Reading that
record exhausts MRTRY and reports a data error. This satisfies SADIE's EGP test
without emulating physical gaps or CRC circuitry.

For write-protected diagnostic/installation media, mount a ZIP member:

```sh
zip -j build/sadie-protected.zip roms/tapes/sadie-3.5.tap
```

Use `-tape1 build/sadie-protected.zip/sadie-3.5.tap`. For TCOM and TEX, SADIE
asks you to replace its cartridge with scratch media after loading the test;
use File Manager to mount a blank writable TAP before continuing.

### DEI 3400 cartridge capacity evidence

The [S8000 Hardware Reference Manual, March 1982](https://www.bitsavers.org/pdf/zilog/s8000/03-3198-01_System_8000_Hardware_Reference_Manual_Mar1982.pdf)
lists four tracks and 6,400 bits/inch in table 2-4 (printed page 12), with
30 inches/second read/write and 90 inches/second rewind/search. Its system
description on printed page 1 calls the cartridge drive a 17-megabyte unit.
The [DILOG DQ320 brochure, June 1981](https://www.bitsavers.org/pdf/dilog/brochures/DQ320_Brochure_Jun1981.pdf)
explicitly supports the DEI Model 3400 and specifies up to 17 MB on a
450-foot cartridge.

The [WICAT System 150 Hardware Reference Manual, September 1983](https://www.bitsavers.org/pdf/wicat/ws-150/187-055-201B_WICAT_System_150_Hardware_Reference_Manual_Sep83.pdf)
provides additional DEI drive information in chapter 6. Section 6.1 refers to
the DEI Series CMTD-3400B2 operation and maintenance manual. Section 6.4 gives
a minimum interblock gap of 1.2 inches and four tracks. Table 6-C on printed
page 6-12 (PDF page 102) documents both 300- and 450-foot tapes.

Multiplying nominal length by 6,400 bits/inch gives these **raw upper bounds**,
before load/end margins, gaps, framing and check characters; these are
calculations, not usable payload specifications:

| Nominal length | Raw byte equivalent per track | Four-track total |
|---|---:|---:|
| 300 feet | 2,880,000 | 11,520,000 |
| 450 feet | 4,320,000 | 17,280,000 |

Usable payload depends on record size. For example, WICAT table 6-C gives
5.3 MB per 450-foot tape with 500-byte records, and 13.4 MB with 8,192-byte
records, assuming 1% file-mark content. These are WICAT formatter figures,
not established Zilog capacities: WICAT figure 6.3 uses parity-bearing
nine-bit characters and an LRCC, while the Zilog controller's framing and
gap generation need separate verification. The DEI transport specifications
alone do not justify copying WICAT's format accounting into the TCC.

A cartridge-length model should select 300 or 450 feet for the mounted
medium, and account for each record/file mark's tape occupation at the
logical image level. No flux emulation or CRC calculation is necessary to
account for the space these consume. The diagnostic scratch limit should
remain a separate test override. Tpaxia's TAP records and track markers do
not identify cartridge length, so it cannot be inferred from TAP file size;
an explicit medium setting or associated metadata is needed. No verified
600-foot compatibility specification has been found, so it should not be
offered as supported DEI 3400 media merely by extrapolating tape length.

## Starting SADIE

```sh
./s8000d s8000 -slot_disk mwdcii -slot_tape tcc \
  -tape1 roms/tapes/sadie-3.5.tap -rompath roms \
  -slot_cpu:cpu_a:sio0:chb:console terminal \
  -window -ui_active -uimodekey F12
```

At the monitor banner type **`Z T`**, including the space, and press Return.
This runs the original monitor's cartridge loader, then the tape's primary
bootstrap and SADIE executive. START uses the selected default disk device;
`Z T` explicitly chooses tape. Use File Manager to mount a different TAP.
The console starts at 9600 baud, 8 data bits, no parity, one stop bit.

## Installing ZEUS from TAP

The same launch command with `-tape1 roms/tapes/zeus-3.21-install.tap` boots
the original ZEUS secondary loader. Add `-hard1` to attach a writable MWDCII
disk. At its `Boot` prompt use the original `ct(0,2)`, `ct(0,3)` and `ct(0,4)`
utilities for block zero, filesystems and restore, as described in the MWDCII
notes. Use a type-3 disk for the factory partition layout.

The installation harness now accepts `--tape`; in that mode it sends `Z T`
to the original monitor and supplies console answers. It does not inject a
bootstrap, replace CT routines or install logical-file I/O hooks:

```sh
python3 scripts/s8000/install_zeus.py \
  --tape roms/tapes/zeus-3.21-install.tap \
  --disk build/s8000-tcc-zeus-install.chd \
  --output build/s8000-tcc-zeus-final --timeout 1800
```

Installation replaces disk contents; use a disposable formatted/seeded image.
The harness also performs the vendor `/etc/makenewfs` post-install setup and
syncs before exiting. It creates the root/usr aliases and initializes `/tmp`
and `/z`, which are required for clean multi-user bringup. `--stage boot` and
`--stage multiuser` use TAP to load the secondary bootstrap, then boot the
installed disk. Multi-user console operation changes to 9600 **7E1** at login.

The completed native installation is `build/s8000-tcc-zeus-install.chd`.
Root and `/usr` were restored from the unmodified TAP, `/tmp` and `/z` were
initialized, and the single-user shell booted after restarting MAME. Multi-user
startup, the `zeus`/`jupiter` login and all four mounts also passed. The original
kernel CT driver read a complete 512-byte bootstrap record from the cartridge
using interrupt-driven DMA, both in single-user mode and after login. See
`build/s8000-tcc-zeus-multiuser/console.txt` for the completed check. The older
`s8000-mwdcii-zeus*.chd` images were not changed. To launch this disk with tape
available, use:

```sh
./s8000d s8000 -slot_disk mwdcii -slot_tape tcc \
  -hard1 build/s8000-tcc-zeus-install.chd \
  -tape1 roms/tapes/zeus-3.21-install.tap -rompath roms \
  -cfg_directory build/s8000-tcc-zeus-final/cfg \
  -slot_cpu:cpu_a:sio0:chb:console terminal \
  -window -ui_active -uimodekey F12
```

Type `Z T`, then `md(0,15200)zeus` at the secondary loader's `Boot` prompt.
The saved configuration selects CPU-A's segmented-memory jumper and the MD
disk default. Enter `/etc/INIT 2` for multi-user startup; switch the terminal
to 7 data bits and even parity at login. Restore 8N1 before the next reset.

## Host registers and a correction to the firmware notes

The command and status definitions come from
[Tpaxia's TCC research](https://github.com/tpaxia/Zilog_S8000/blob/5c874c92c7968812dd1a1368e8053159726341fa/TCC.md)
and the supplied ROMs. Two details are essential for native software:

* At `46H`, address bits 16–23 occupy **D15–D8**. D7–D0 are address bits
  24–31, required to be zero. DMA advances across 64 KiB boundaries.
* At `48H`, a host write programs the bound, while completion returns
  **bytes transferred**, not residual bytes. Firmware `0333–033f` sets HL
  from IY (original count), then `018f` subtracts BC (remaining count).
  The standalone CT driver reads that result directly at `2f90`. The pinned
  TCC.md interpretation of this as residual is incorrect; implementing it
  that way causes `sarestor` to calculate zero-length requests and fail.

READ transfers one record, silently discards data beyond the requested bound,
and reports an actual odd length for an odd record. DMA remains word-aligned.
A file mark returns zero transferred bytes and FMDET|INAP (`0012`), with
controller status bit 10 set, matching firmware `0179–0189`. File marks are
not data records. The interrupt vector is at `40H`; bit 9 reports BUSY.
Interrupt control at `4eH` supports asynchronous completions and the ZBI daisy
chain. Rewriting control `0003` clears both the pending and in-service latches
while keeping interrupts enabled. The kernel CT ISR acknowledges the board
this way rather than issuing the CPU board's synthetic Z80 RETI. DIAG models
the host's `5555`/`AAAA` latch handshake; it does not test
the omitted physical formatter.

SADIE's TCU diagnostics exposed two DIAG handshake requirements: TCUMON
checks the registers in descending order, and reads back each `AAAA` write
before waiting for BUSY to clear. Completion therefore waits for **all**
registers, with a delay before clearing the pattern. Firmware `0a36–0a3a`
also restores the saved interrupt control and vector. These are preserved so
interactive `DIAG1` does not disable the next interrupt-driven tape command.

## Verification

```sh
python3 scripts/s8000/check_tcc.py --sadie roms/tapes/sadie-3.5.tap
python3 scripts/s8000/check_sadie.py --tape roms/tapes/sadie-3.5.tap \
  --output build/s8000-tcc-sadie-final
```

The controller probe exercises all four tracks and drive selections, DMA
carry, odd and truncated records, actual transfer counts, file marks,
forward/reverse positioning, invalid parameters, write protection and repeated
interrupt flags. It rejects seven malformed TAP variants. Independent SADIE
extracts match track 0 file 1 (27,648 bytes), track 1 file 0 (24,576 bytes),
and track 2 files 0/1/2 (8,000/1,000/1,300 bytes). Native `Z T` boot loads the
executive and MDCTEST 4.2 from TAP; with no disk it exits on the expected
`Power-up Test, Drive Not Selected` result.

With a disposable type-0 disk, native TAP-loaded MDCTEST test 2 performs
50 random-length write/read cycles and exits with zero errors. The transcript
is `build/s8000-tcc-sadie-disk/console.txt`. The full native installation and
post-install setup passed in `build/s8000-tcc-zeus-final/console.txt`.

The optional `--check-tape` check opens `/dev/rct0a` through the original ZEUS
kernel driver, reads one 512-byte record with `dd`, checks the bootstrap's
hex dump, removes its temporary file and syncs. This exercises interrupt
acknowledgement and DMA through the kernel's physical buffer mapping, beyond
the polling transport used by the standalone installer:

```sh
python3 scripts/s8000/install_zeus.py --stage multiuser --check-tape \
  --tape roms/tapes/zeus-3.21-install.tap \
  --disk build/s8000-tcc-zeus-install.chd \
  --output build/s8000-tcc-zeus-multiuser --timeout 300
```

## ZEUS kernel tape writes

The kernel CT driver also completed a write/read round trip: `dd` copied the
first 512 bytes of `/zeus` to scratch tape, read them back, and both `od -x`
dumps matched. This exercises DMA, interrupts, rewind and close-time file
marks. The resulting TAP contains one 512-byte record followed by a file
mark and remains valid when mounted again. The verified transcript is
`build/s8000-tcc-kernel-write/verified/console.txt`.

`install_zeus.py --stage boot --check-tape-write --tape ... --disk ...` repeats
this check. **It overwrites the mounted tape**; supply a disposable copy of
the installation TAP (needed to boot the secondary loader) and a copy of the
installed CHD. `--check-tape` remains the read-only bootstrap check.

## SADIE cartridge diagnostics

The native cartridge-specific diagnostics have now been tried, separately
from the MWDCII tests. The harness boots a disposable SADIE copy and mounts a separate blank scratch
cartridge when SADIE requests it; source media and installed disks are untouched.

| SADIE choice | Diagnostic | Observed result |
|---|---|---|
| 17 | TCUMON 3.1 | Power-on and `DIAG1` complete without register errors; LOAD, MODE, track 0/1/2 reads, SKBF/SKBR, REWIND and SKFF complete, then Q exits normally |
| 18 | TCOM 2.1 | All six command modules complete; `LAP 1 COMPLETE, ERROR COUNT = 0` |
| 19 | TEX 2.0 | Completes tracks 0–3 with zero hard/soft read/write or compare errors; 256 KiB per-track scratch capacity, parameter 2 = `010a` (one read pass) |

The initial TCUMON run reported incorrect `AAAA` readbacks, and its `DIAG1`
then disabled subsequent interrupt completion. Both bugs were corrected in
the controller; the ascending/descending register tests and saved interrupt
settings are now covered by `probe_tcc.lua` too. This is verification of the
emulated host interface, not execution of the physical board's FIFO/CRC test.
The writable runs also corrected logical BOT in MODE 0, file-mark reporting
on block skips, forward/reverse file positioning, repeated UNLOAD rejection,
and bounded end-of-tape handling. The small-capacity TEX run verifies the HLE
transport and data comparison, not full-size cartridge timing or reliability.

Reproduce the runs with:

```sh
python3 scripts/s8000/check_sadie_tcu.py --diagnostic TCUMON \
  --output build/s8000-tcu-tcumon-write-regression --timeout 180
python3 scripts/s8000/check_sadie_tcu.py --diagnostic TCOM \
  --output build/s8000-tcu-tcom-write-verified --timeout 300
python3 scripts/s8000/check_sadie_tcu.py --diagnostic TEX \
  --output build/s8000-tcu-tex-write-verified --timeout 300
```

Each directory contains `console.txt`, a controller register trace in
`mame.log`, the disposable `scratch-sadie.tap`, and (for destructive tests)
`scratch-blank.tap`. The harness checks completion and error totals before
reporting PASS. The lower-level `check_tcc.py` additionally verifies exact
persisted TAP bytes, overwrite truncation, cartridge creation, preservation
of other tracks, protected ZIP media and unload/reload readback.
